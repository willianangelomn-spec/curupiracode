# CurupiraCode Chrome 与 Edge 扩展

[English](README.md) | 中文

Manifest V3 扩展，提供持久侧边栏对话、经审阅的浏览器自动化、受限表单回答和可移植表单宏。它复用本地 CurupiraCode 已配置的模型，不包含 API key。

## 开发安装

1. 在仓库根目录运行 `pnpm --filter @deepseek-ai/dsh-browser-extension build`。
2. 打开 `chrome://extensions` 或 `edge://extensions`。
3. 启用开发者模式并选择 **加载已解压的扩展程序**。
4. 选择 `apps/browser-extension/dist`。
5. 保持 CurupiraCode 在 `http://127.0.0.1:3080` 运行，然后点击扩展图标。

manifest 的 `key` 固定 id `ndfighammhdpfaejmadojjaaelmpadek`。本地服务器仅通过回环地址接受该 id 的 RPC；其他扩展和普通页面会收到 HTTP 403。

## 安全流程

**对话**标签页保留一个 CurupiraCode 会话，并在面板重新打开时恢复历史。**包含当前页面**仅在用户发送消息时捕获标题、URL、选中文本和可见文本。不含工具的 `browser-chat` preset 会把捕获内容视为不可信数据。**新建对话**会开始另一个会话，而不会删除较早的 CurupiraCode 历史。

在**自动化**中，用户明确选择**读取页面**或**使用 Curupira 规划**。扩展捕获有界可见文本和最多 250 个控件，不包含字段当前值。不含工具的 `browser` preset 生成经过本地校验的预览。只有**执行已批准操作**会修改页面；提交、购买、支付、发布和删除需要额外确认。密码、验证码、支付卡、上传和浏览器内部页面保持阻止状态。

**回答表单**接收用户提供的事实和标准，然后要求 Curupira 把问题、必填字段、描述和选项映射为带置信度的建议答案。每个答案都可编辑并可单独选择；低置信度答案默认禁用。该模式只接受 `fill`、`select` 和 `check`，因此模型输出无法点击或提交表单。最终提交始终由用户手动完成。

**复制宏**记录用户填写 `input`、`textarea`、`select`、checkbox 和 radio 控件的方式，以及中间的**下一步**、**继续**和**前进**按钮。语义指纹使用字段类型、名称、标签、问题上下文和无障碍属性，而不是坐标或可执行 selector。录制覆盖已授权 frame 和同站点页面，合并重复变化，并移除最后一页的所有跳转，因此重放会在最终提交前停止。敏感字段和上传字段绝不会进入宏。

宏保存在 `chrome.storage.local`，可以删除或导出为 JSON 并用于另一安装。导出文件包含已输入值，必须视为个人数据。导入会在重放前校验版本、限制、操作类型和单一 HTTP 来源。

## 模型体验

### 浏览器规划

#### 模型所见

选中的模型会收到明确标记为不可信文本的有界页面快照或合格表单快照。模型不会获得浏览器执行工具；它只返回一个由扩展校验和预览的 JSON 计划。

#### Token 影响

捕获的可见文本和控件元数据会增加输入 token。宏录制和重放是确定性本地操作，不使用模型 token。

#### KV Cache 影响

每个新页面快照都可能改变稳定受限 preset 之后的请求。不带页面上下文的对话可以保留更稳定的前缀。

## 已知限制与后续工作

- 自动化一次处理一个已捕获页面；导航后需要重新捕获和规划。
- 支持的规划操作为 `click`、`fill`、`select`、`check` 和 `scroll`；表单模式将其缩小为 `fill`、`select` 和 `check`。
- Firefox 需要独立的 `sidebar_action` manifest，仍属于后续工作。
- 稳定扩展 id 用于识别已安装来源，但不认证个人，因此桥接保持仅限回环。
