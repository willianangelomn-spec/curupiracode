# Agent Note：Curupira 语义记忆与会话删除

状态：已实现

[English](2026-08-30-curupira-semantic-memory-and-session-deletion.md) | 中文

## 问题

Curupira Memória 需要按含义检索用户明确授权的资料，而不只是匹配相同词语；同时，在没有托管模型或 API 密钥时仍须可用。会话列表也需要清楚区分可恢复的归档与永久删除，以便安全清理无用的测试对话。

两项能力都必须属于可分发组合，不能依赖贡献者个人路径、预先填充的本机缓存或私有服务。

## 决策

本地知识存储保留 SQLite FTS5 作为强制基线，并通过 Transformers.js 增加可选的本地多语言嵌入。默认模型为 `Xenova/multilingual-e5-small`，以量化 ONNX 权重延迟加载，并缓存到带版本的知识库目录中。搜索融合词法和语义候选，为已有段落补建向量，并保存归一化文档中心向量供 `knowledge_related` 使用。可恢复的模型或下载故障只记录一次，词法搜索继续工作。

基础知识工具注册 `knowledge_related`，并增加系统提示段：当请求可能依赖用户资料库时，代理应主动搜索、保留段落来源且不得伪造引用。内容寻址的原始文件保持不变。本里程碑提供语义引擎和关系 API；类似 Obsidian 的关系图和编辑界面属于后续界面里程碑。

每个普通会话行现在都在现有非破坏性归档旁提供破坏性的 `Apagar conversa` 操作。界面要求明确确认。RPC 拒绝删除子代理拥有或由其他消费者持有的活动会话；对于本 Host 拥有的活动代理，会先有序释放，再解除工作区关系，并永久删除 JSONL 或 SQLite 中的持久会话数据。在 Host 具备真正的远程身份验证前，此破坏性 RPC 仅允许回环访问。

## 可移植性

代码中没有个人文件系统路径。资料库依次默认为 `<DSH_HOME>/knowledge/v1`、`<CURUPIRA_HOME>/knowledge/v1`，最后是当前用户主目录下的 Harness 目录。模型在第一次语义使用时下载到 `<vault>/models`，之后可离线复用。全新安装会从仓库获得依赖、插件组合、数据库迁移、回退行为和界面本地化文本。

## 验证

存储测试覆盖无共同关键词的语义检索、相关文档排序、向量补建、词法回退、来源、去重和删除。真实 ONNX 冒烟测试通过可移植缓存生成了归一化的 384 维向量。会话测试覆盖 JSONL 和 SQLite 持久删除、API 传输、确认门槛、危险样式和客户端状态移除。客户端包和本地 Web 组合均可构建并在重启后提供服务。

## 考虑过的替代方案

**强制使用托管嵌入 API。** 已拒绝，因为本地第二大脑必须在没有额外凭据、持续费用或泄露私人资料文本的情况下工作。

**用神经搜索完全替代 FTS5。** 已拒绝，因为首次模型下载、硬件不支持或模型不可用都不应使检索失效；混合搜索还能保留精确词语检索能力。

**仅用归档处理不需要的对话。** 已拒绝，因为归档有意设计为可恢复，并会保留持久对话。两个操作现在明确表达不同的数据保留结果。

**不检查所有权，直接按标识删除活动会话。** 已拒绝，因为其他 Host 消费者或父代理可能持有需要有序释放的能力。删除仅适用于本 Host 能安全拥有的普通会话。

## 后果

Curupira Memória 能在本地发现葡萄牙语和多语言概念匹配并暴露相关资料，无需 Gemini、DeepSeek 或其他付费 API。第一次神经搜索可能因下载模型而较慢；当前语义排序在进程内最多扫描 50,000 个段落向量，更大的资料库将需要专用的近似最近邻索引。永久删除无法撤销，因此确认框会说明边界，而归档继续用于可恢复的整理。
