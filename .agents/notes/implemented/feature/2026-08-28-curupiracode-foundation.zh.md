# Agent Note: CurupiraCode foundation

Status: implemented

[English](2026-08-28-curupiracode-foundation.md) | 中文

## Problem

派生项目需要一个不会被误认为 DeepSeek 官方发行版的独立身份，同时要保留足够的包兼容性，以便继续使用现有插件生态。面向本地优先的发行版还需要在首次启动时即可搜索，而不要求用户再提供一份商业服务凭据；所有发布能力都必须能在创始贡献者的电脑之外复现。

## Decision

产品对外统一使用 CurupiraCode。Web 文档、PWA 元数据、品牌插槽、欢迎文案、CLI 帮助和就绪提示均使用该名称。标志由开放的路径／电路形 C 和反向脚印组成；公共命令为 `curupiracode`，`dsh` 保留为兼容别名。

在基础阶段，`@deepseek-ai/dsh-*` 内部包名、配置目录、环境变量和稳定协议标识保持不变。它们的迁移属于单独版本化的兼容性项目，因为同时更改会破坏已安装插件、保存的配置和自动化，却不会改善用户可见产品。

基础 bundle 挂载 `@deepseek-ai/dsh-web-search-duckduckgo` 并选择 `duckduckgo-html`。该提供方通过 DuckDuckGo HTML 获取普通结果；主响应失败或为空后回退到 Bing HTML；可选混合带日期的 Google News RSS 条目；不需要凭据。多引擎回退方向归功于 `dsh-free-web-search`，实现仍原生基于提供方无关的 `ctx.web` seam，并遵守 Harness 的重定向与生命周期规则。

bundle 还挂载 `@deepseek-ai/dsh-web-search-searxng`，作为配置前不可用的替代项。它从行配置或 `SEARXNG_URL` 解析运营者控制的端点，要求 JSON 输出，拒绝重定向，并且不会选择或硬编码公共实例。现有 DeepSeek 搜索提供方仍作为另一个显式可选方案挂载。

根文档说明派生关系、独立地位、MIT 继承、第三方启发、视觉规则和里程碑路线图。在 CurupiraCode 公共仓库或包注册项真正存在前，文档不宣称它们已经发布。仓库代码和可发布配置不包含个人文件系统路径、账户密码或有效的 OpenRouter 风格密钥。

## Verification

品牌插槽测试覆盖注册、卸载、wordmark 可访问性和宿主指定的标志尺寸。无密钥提供方测试覆盖重定向展开、DuckDuckGo／Bing HTML 与 RSS 解析、回退、结果上限、可选新闻源失败、请求映射和无凭据注册。SearXNG 测试覆盖 JSON 映射、无效行过滤、端点构造、表单字段、中止／错误分类、环境解析、HMR 卸载以及通过真实 Loader 组合加载命名插件。Host 与 Client 构建包含新包和品牌界面产物；组合后的 Web 配置只选择 `duckduckgo-html`，SearXNG 在配置前保持不可用。

## Alternatives considered

**立即重命名所有包和持久化标识。** 放弃该方案，因为这会迫使插件和本地配置进行一次性整体迁移。对外身份可以先独立，兼容层则应有计划地迁移。

**只在用户个人配置中保留无密钥搜索。** 放弃该方案，因为本地补丁不是可复现的产品能力，并且不会出现在任何全新安装中。

**把 `dsh-free-web-search` 作为一个整体插件引入。** 放弃该方案，因为它会重复现有 web 工具和提供方包，在共享 seam 之外引入提供方专有请求字段，并包含一个不具备仓库 SSRF 控制且会跟随重定向的通用抓取路径。CurupiraCode 改为在小型、可测试的原生提供方中采用有价值的多引擎思路，并保留归属说明。

**自动轮换公共 SearXNG 实例。** 放弃该方案，因为实例可用性和 JSON 策略会各自变化，静默路由会使隐私和数据目的地不可预测。运营者必须显式选择端点。

**保留上游公开品牌并增加副标题。** 放弃该方案，因为它可能造成用户混淆，并与上游针对派生项目的品牌指引冲突。

## Consequences

用户会看到一致的独立产品，并且首次启动即可在不增加密钥的情况下搜索。DuckDuckGo 故障时可以回退到 Bing，重视隐私的部署则可以选择自己的 SearXNG 实例。现有插件继续加载；代价是内部 `dsh` 术语会继续出现在维护和诊断工具中，直到命名空间迁移方案完成。公共 HTML 与 RSS 端点可能变化或受到限流，因此解析行为由固定样例测试覆盖，故障仍按提供方错误处理，而不是承诺商业 SLA。
